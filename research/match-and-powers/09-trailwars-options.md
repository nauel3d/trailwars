# Trail Wars match options — original proposals for approval

## Recommendation

Launch with steering-only **Circuit**, retain the existing quick single-round practice as an onboarding option, and defer active powers to a separately labeled experimental **Chaos** playlist. Do not port reference score stealing, stat-bearing unlocks or all31 effects into the first release. This preserves a clear promise: outlast rivals, learn tight turns, see cumulative progress, try again. Existing SNAP ARCADE art, compact mobile Home and navigation stay intact.

These are proposed Trail Wars rules (T), not recovered Curve Fever behavior. The isolated MatchSeries proof is permitted research code and never switches the current default mode. Owner approval is required to replace a live lifecycle or choose future prototype effects.

The capped durations are arithmetic budgets, not playtest measurements. Both formats use2–6 players, no purchases, powers, random gaps or rank stakes. A server disconnect forfeits that player's current round and removes them from later rounds; emitted trails follow the existing engine rule until round reset. No mid-series entrants change the competitive roster; joiners spectate/queue for the next series. If fewer than two competitors remain, finish by abandonment with no competitive rewards. These are original fairness rules requiring approval.

## Why powers should come later

The installed design combines equipped defense, variable score formulas, reflect ownership, projectile hit rules, status cancellation, throw timing, carried cooldowns and mode overrides. Adding only an icon/cooldown would conceal most of the mechanic. Two steering controls already need physical-phone/controller validation. Separate powers protect the accessibility of the core playlist and make server verification and balance tractable.

If the owner chooses a future isolated2–3-effect proof, assess these original families:

1. **Short trail crossing:** a brief, readable crossing opportunity with a telegraph and exit rule; no wall immunity. Medium collision/order risk. It should not imply full invulnerability.
2. **One clear projectile:** one visible, bounded-life bolt with a simple hit consequence chosen before coding. No homing, score stealing or reflective ownership chain initially. Medium/high networking and targeting burden.
3. **Small trail eraser:** a bounded region and precise rule for which trail segments become nonlethal. High collision/render-resync risk; implement only after hit geometry supports reversible segmentation.

No effects are implemented here. Names, numeric balance, targeting, friendly fire, cooldown carry, hit consequences and controller/touch activation require an explicit owner choice. The framework blueprint lists the necessary tests; a blank or green test suite must not stand in for unbuilt power behavior.
