# Round and networking contract before implementation

Initial local proof: one human and three deterministic bots. States: Waiting → Countdown → Active → Results; rematch starts a new match identity. Last surviving core wins; zero survivors at the same event produces a draw. Eliminated players spectate; leaving/disconnecting removes their live core while existing trails remain until round reset. Countdown and maximum duration are custom tunables. No powers or paid gameplay advantages.

Server extension: 2–6 humans in a single server arena. Clients submit only validated join/rematch/leave and sequenced steering intents, never positions, collisions, winners or rewards. Reject malformed/extra fields, NaN, invalid steering, stale sequences, wrong match IDs and rate floods. Steering leases expire to neutral, preventing a lost release or disconnected controller from holding a turn forever. Client prediction is visual and reconciles to server snapshots; it cannot decide elimination.

Choose an explicit pure-Luau fixed-step simulation and RemoteEvents for this custom nonphysics 2D engine. Roblox's current [server authority model](https://create.roblox.com/docs/projects/server-authority) provides prediction/rollback for its fixed-simulation architecture but requires multiple engine settings, including authority mode, input action integration and streaming. Do not enable these experimental/dependent settings for a UI-coordinate simulation without a proof. [Remote events](https://create.roblox.com/docs/scripting/events/remote) and strict [boundary validation](https://create.roblox.com/docs/scripting/security/client-server-boundary) provide a smaller verified route here. Evaluate unreliable snapshots only after reliable, bounded deltas work.

Server-finalized match IDs alone may call the existing EconomyService.roundReward through ProfileStore.transact. Exactly-once tombstones, retries and anti-AFK eligibility are required. Practice bots must not become a production currency farm. Production profiles and purchases remain disabled. Studio tests use mock persistence and label this honestly. The decorative Home model stays independent of the real simulation.

Milestones B–E source and bounded F checks are now implemented in the explicit gameplay projects. See qa/gameplay/verified-checkpoint.md for actual Roblox two-client results and CPU measurements. Remaining gates include full six-client engine stress, live adverse-network tests and physical-device usability. Production default bootstraps are preserved; the gameplay adapter currently uses isolated mock persistence only.
